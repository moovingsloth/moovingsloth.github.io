02Problem

Goal: a camera streaming environment that SLAM could run on.

(1)

Robot middleware (CycloneDDS) communication did not work across LAN + WiFi; the starting send/receive code failed.

(2)

The bridge between networks dropped packets, WiFi/AP switching broke routing, and UDP buffers overflowed under image load.

03Approach
1.

Image transport — designed the image message format and built Python/C++ send/receive for depth and stereo cameras.

2.

Cross-network bridge — fixed packet drops with IP forwarding, NAT and route control.

3.

Network automation — auto-reset routes on WiFi/AP switch and auto-discover the bridge, so no manual config.

4.

Stability — raised UDP buffers, tuned resolution/FPS for latency vs quality, per-camera multithreading.

5.

Deployment — systemd auto-start/restart, Cython packaging, docs and handover.

04Results

Streaming working end to end (LAN, WiFi and AP mode) and reproduced on a new device.

End-to-end Python implementation, with parts in C++.
