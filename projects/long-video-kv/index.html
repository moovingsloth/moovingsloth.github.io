Memory-Efficient Long-Video Understanding (Capstone)

Lee DongWon · Jun. 2026 – Present

Overview

With streaming long video, the KV cache grows with the number of frames: Qwen2-VL-7B at 768 frames holds about 50K tokens of full KV. InfiniPot-V compresses it to a 6K budget. I store the kept KV cache in INT4 instead of FP16. At the same 6K budget, INT4 reaches Video-MME 63.5 vs 62.8 and MLVU 66.1 vs 65.8 (FP16), using about 1/3.1 the KV bytes (164 B vs 512 B per token per head).

Approach

  • InfiniPot-V (TaR + VaN + Pool) compresses the KV cache to a 6K budget.
  • The kept KV is stored as INT4 KIVI: keys quantized per channel, values per token, group size 32, and the most recent 128 tokens kept in FP16.
  • Compared against FP16 at 6K, at equal KV bytes.
  • Model: Qwen2-VL-7B. Benchmarks: Video-MME and MLVU.

My Role

  • Added INT4 KIVI KV storage on top of InfiniPot-V.
  • Ran ablations, using the best setting (including Pool) as the baseline.
  • Built the Video-MME / MLVU evaluation pipeline on a Slurm GPU cluster.

Tech: PyTorch, KV-cache quantization.
